# Translations

The interface is available in five languages: en, de, it, es, fr (the same as bf-frontend). The language is a per-admin preference, not part of the URL: there is no locale routing and no `[locale]` segment.

- **No hard-coded UI text.** Every string a user can see or a screen reader can announce (labels, placeholders, `aria-label`, toasts, empty and error states) comes from `useTranslations()` (next-intl). This includes shared components in `src/components/`.
- **Adding a string:** add the key to `messages/en.json` first (English is the source of truth), then add the same key to `de.json`, `it.json`, `es.json` and `fr.json` in the same change. Never leave a language behind or fall back to English on purpose.
- **Keys** are grouped by area (`common`, `shell`, `userMenu`, `table`, `resources`), nested, camelCase, and named after what the text is for, not its wording. Reuse `common` only for text that is truly the same everywhere.
- **Variables and plurals** use ICU syntax in the message (`{count, plural, one {…} other {…}}`, `{label}`); never build sentences by joining strings in code. Use `t.rich` with a tag (`<range>…</range>`) when part of a message needs its own styling.
- **Formatting:** numbers, money, dates, times and country names go through `useFormat()` from `@/i18n/use-format`. Never call `toLocaleString`, `Intl.*` with a fixed locale, or hand-format a date.
- **Backend text is not translated here.** Resource labels, field labels, option labels, navigation labels, action labels and error messages arrive already translated from the API (it reads `Accept-Language`, which the i18n provider keeps in sync). Do not add them to `messages/`. The mock data is English only for that reason.
- **Checks:** message keys are type-checked (a wrong key fails `npm run build`), and `npm run i18n:check` (part of `npm run lint`) fails when a language has missing or extra keys or different placeholders.
- Files in `src/components/ui/` are generated by shadcn; their few built-in screen-reader strings are left as generated.
